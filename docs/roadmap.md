# CoSMiT 实施路线

## M0：项目基线（当前）

- 统一 CoSMiT 名称和边界。
- 固化六阶段、领域模型、配置和 artifact 名称。
- 建立 CLI、测试与文档。

完成标准：`show-pipeline`、双向配置校验、单元测试和最小端到端动态执行通过。

## M1：目标组件画像与关键性

- 实现框架仓库、文档、测试、Git 和 issue 数据 ports。
- 定义组件目录和五维证据 schema。
- 完成 TensorFlow/PyTorch 组件扫描、测试索引与双向关键性排序。

完成标准：对 TF→PT 和 PT→TF 首批目标组件生成可人工审查、可重放的关键性报告。

## M2：六维相似组件检索

- 实现源框架组件目录。
- 分别计算六维证据，构建候选生成与重排。
- 建立人工映射金标准和检索评估脚本。

完成标准：输出 Top-K、分维证据、不等价条件和 RQ2 指标。

## M3：测试知识中间表示

- 建立语言无关、框架可扩展的 Test Knowledge IR schema。
- 实现 Python AST/控制流/数据流抽取。
- 完成九类测试意图与参数约束识别。

完成标准：随机抽检能还原源测试的核心输入、执行和 oracle，且有一致性指标。

## M4：可追溯测试迁移

- 实现 API、参数、输入、断言和测试设施五类变换。
- 引入受 schema 约束的生成器或 LLM port。
- 生成目标框架原生测试与 transformation log。

完成标准：候选代码可逐项解释，任何行可追溯到知识单元或明确的适配规则。

## M5：验证与反馈修复

- 实现静态检查、隔离执行和错误分类。
- 实现有限轮次、受约束的修复协议。
- 建立源测试稳定性与目标测试意图保持检查。

完成标准：每个候选进入明确状态，所有修复有前后证据，不存在静默丢弃。

## M6：排序、扩展与实验

- 实现差分输出、梯度和数值误差分析。
- 建立价值评分和 shape/dtype/device/边界扩展。
- 完成 RQ1-RQ5、消融、统计检验和缺陷复核。

完成标准：产出可复现实验包、目标框架测试集和研究报告。

## 当前禁止事项

- 不提前开发“万能迁移 prompt”。
- 不在组件映射和 Test Knowledge IR 稳定前批量生成测试。
- 不以通过率替代有效率。
- 不把临时脚本输出直接当作正式 artifact。
- 不把未验证的跨框架差异直接报告为缺陷。
