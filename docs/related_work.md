# CoSMiT 相关工作

## 1. 深度学习库测试输入生成

[FreeFuzz](https://doi.org/10.1145/3510003.3510041) 从开源代码中挖掘 API 调用并进行差分模糊测试，核心优势是复用真实调用作为种子；[DeepREL](https://doi.org/10.1145/3540250.3549085) 自动推断同一库内的关系 API，以扩大可用差分关系；[NNSmith](https://doi.org/10.1145/3575693.3575707) 使用轻量算子规范和约束求解生成有效计算图。

这类工作主要回答“如何生成有效且多样的输入”。CoSMiT 的起点不同：先从目标框架测试缺口选择组件，再把源框架已有测试中的输入、执行、断言和意图作为整体知识迁移。输入生成是第六阶段的增强手段，不是系统的唯一目标。

## 2. 跨框架差分测试

[TensorScope](https://www.usenix.org/conference/usenixsecurity23/presentation/deng-zizhuang) 从模型转换器提取 counterpart API 和参数关系，联合分析跨框架约束并进行差分测试。它证明了 counterpart、参数对齐和联合约束对跨框架测试的重要性。

CoSMiT 与其最接近，但研究问题不同：TensorScope 从已知 counterpart API 出发生成差分输入；CoSMiT 先识别目标关键组件，使用名称、文档、参数、源码、上下文和测试行为六维证据检索多个源组件，并迁移完整测试资产。CoSMiT 还把测试意图保持和目标框架原生测试产出作为验收条件。

## 3. 跨项目缺陷知识迁移

[CrossProbe](https://doi.org/10.1145/3728984) 使用 LLM 从一个框架的已有 issue 学习缺陷知识，再向其他框架生成测试。这说明跨项目知识可以用于发现镜像缺陷。

CoSMiT 不以 issue 文本为唯一知识源，而以可执行源测试为核心证据；issue 和缺陷历史主要用于关键性评分及回归意图补充。最终产物必须保留源测试结构、断言 oracle 和转换轨迹。

## 4. 组件匹配与模型转换

模型转换工具关注模型或算子语义的可执行转换，组件匹配研究关注 counterpart 发现。这些结果可以提供候选映射，但不自动等价于测试知识迁移：测试还包含异常类型、容忍阈值、梯度、测试基础设施、随机性和回归语境。

CoSMiT 因此把组件映射定义为带六维证据和不等价条件的关系，而不是一个字符串字典；映射只是第三、四阶段的输入。

## 5. 定位矩阵

| 方向 | 典型输入 | 主要产物 | CoSMiT 的差异 |
| --- | --- | --- | --- |
| API 模糊测试 | 开源调用、API 文档、关系 API | 新测试输入、差分结果 | 以目标测试缺口和已有测试知识为起点 |
| 跨框架差分测试 | counterpart API、约束 | 跨框架不一致 | 同时产出目标框架原生测试资产 |
| 跨项目缺陷迁移 | issue、历史缺陷 | 缺陷触发测试 | 以可执行测试结构和意图为核心知识 |
| 模型/算子转换 | 模型图、映射规则 | 可执行目标模型/调用 | 不以测试 oracle 和意图保持为目标 |
| CoSMiT | 关键组件证据、相似组件、源测试 | 可追溯、验证后的目标测试 | 选择、迁移、验证、排序扩展完整闭环 |

## 6. 研究空缺

现有研究分别覆盖了有效输入生成、关系发现、counterpart 差分和缺陷知识迁移，但仍缺少一条以“目标组件测试缺口”为驱动、把“已有测试意图”作为一等对象、最终交付“目标框架原生测试资产”的端到端路径。CoSMiT 的研究价值应围绕这条组合空缺验证，而不是泛化为所有跨框架测试问题。
